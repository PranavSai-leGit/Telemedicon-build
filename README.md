# MediTale

### *Your health history, connected and ready for every consultation.*

**Primary Hackathon Theme:** Digital Health and Public Health  
**Architecture:** React TypeScript Frontend → FastAPI Python Backend → PostgreSQL (with JSONB) & Gemini AI

---

## 1. Problem Statement & Proposed Solution

### The Challenge
Patients routinely receive medical care across multiple clinics, diagnostic laboratories, and hospitals. Their health histories are fragmented across disparate paper prescriptions, discharge summaries, and PDFs. When attending a new consultation:
- Clinicians lack immediate access to historical diagnoses and medication regimens.
- Crucial drug-to-drug interactions or conflicting dosages go unnoticed.
- Summaries generated by general-purpose LLMs frequently hallucinate facts or fail to cite verifiable evidence.
- Healthcare providers often lack patient consent frameworks for granular record sharing.

### The MediTale Solution
**MediTale** is an AI-powered patient health history and clinical handover platform that:
1. **Unifies Records:** Ingests prescriptions, lab reports, and discharge summaries via PyMuPDF text parsing and OCR fallback with SHA-256 exact duplicate detection.
2. **Extracts Structured Facts into PostgreSQL JSONB:** Stores flexible extraction payloads in JSONB while relational tables enforce foreign keys and queryable timelines.
3. **Connects Ground-Truth Evidence:** Every claim in an AI summary links directly to an extracted fact ID, original file excerpt, page number, and SHA-256 hash.
4. **Reconciles Discrepancies:** Detects potential medication instruction conflicts (e.g., transition from Metformin 500mg BID to 1000mg XR daily) and enables clinician review.
5. **Enforces Strict Backend RBAC:** Multi-tenant role-based access control where clinicians only access documents explicitly authorized via active consent grants, and administrators never see clinical medical documents.
6. **Produces Downloadable Clinical Handovers:** Generates comprehensive PDF handover reports via ReportLab.

## 2. Technology Stack

### Frontend
- **Framework:** React 19 with TypeScript, Vite
- **Styling:** Tailwind CSS v4 with custom light/dark theme variables
- **Icons:** Lucide React
- **Routing:** React Router v7
- **Server State:** TanStack Query
- **Data Visualization:** Recharts for laboratory biomarker trend analysis
- **Security:** HTTP-only cookies, CSRF protection, credentialed fetch

### Backend
- **Framework:** FastAPI (Python 3.14)
- **Database ORM:** SQLAlchemy 2.0 with PostgreSQL JSONB
- **PostgreSQL Driver:** Psycopg 3 (`psycopg[binary]`)
- **Password Hashing:** Argon2 (`argon2-cffi`)
- **Authentication:** Server-side sessions persisted in PostgreSQL with SHA-256 token hashing
- **Testing:** Pytest with FastAPI TestClient

### AI & Document Ingestion
- **AI SDK:** Official Google GenAI Python SDK (`google-genai`)
- **Model:** `gemini-3.8-flash` (configurable via `GEMINI_MODEL`)
- **Validation:** Pydantic structured output models
- **Document Processing:** PyMuPDF (`pymupdf`), Pillow, pytesseract fallback
- **Report Generation:** ReportLab PDF generator

## 3. Architecture & Schema Design

```text
┌─────────────────────────────────────────────────────────────┐
│                 React TypeScript Frontend                   │
│           (Vite + Tailwind CSS + Lucide + Recharts)         │
└──────────────────────────────┬──────────────────────────────┘
                               │ HTTP /api (Cookies + CSRF)
┌──────────────────────────────▼──────────────────────────────┐
│                    FastAPI Backend Node                     │
│  ├── RBAC & Session Security (Argon2, SHA-256)              │
│  ├── Document Parsing (PyMuPDF / OCR Fallback)              │
│  ├── Gemini AI Service (google-genai / Demo Engine)         │
│  ├── Record Reconciliation Engine (Discrepancy Detection)   │
│  └── ReportLab PDF Handover Generator                       │
└──────────────────────────────┬──────────────────────────────┘
                               │ PostgreSQL + psycopg3
┌──────────────────────────────▼──────────────────────────────┐
│                  PostgreSQL Database Engine                 │
│  ├── users (patient, clinician, administrator)              │
│  ├── sessions (server-side hashed sessions)                 │
│  ├── documents (metadata, private path, JSONB extractions)  │
│  ├── extracted_facts (normalized queryable fact relations)  │
│  ├── sharing_grants & sharing_grant_documents (consent)     │
│  ├── discrepancies (reconciliation conflicts & notes)       │
│  ├── summaries (JSONB evidence-linked claims)               │
│  └── audit_events (non-clinical security audit trail)       │
└─────────────────────────────────────────────────────────────┘
```

### Why PostgreSQL with JSONB is Required
Medical documents (prescriptions vs. metabolic panels vs. hospital discharge summaries) possess highly variable structures. MediTale stores the complete validated extraction in a `JSONB` column (`documents.extracted_data` and `summaries.summary_payload`) while normalizing queryable facts into the relational `extracted_facts` table. This provides complete schema flexibility without compromising relational integrity or consent enforcement.

## 5. Quick Setup & Startup Instructions

### Prerequisites
- Python 3.11+
- Node.js 18+ and npm
- PostgreSQL 14+ (Local instance or Docker)

### Option A: Local Setup

1. **Clone the repository:**
   ```bash
   git clone https://github.com/your-username/Telemedicon-build.git
   cd Telemedicon-build
   ```

2. **Configure Environment Variables:**
   Copy `.env.example` to `.env`:
   ```bash
   cp .env.example .env
   ```
   *Edit `.env` to configure your PostgreSQL connection string and optional `GEMINI_API_KEY`.*

3. **Backend Setup:**
   ```bash
   # Create virtual environment
   python -m venv backend/venv
   
   # Windows activation
   .\backend\venv\Scripts\activate
   # Linux/macOS activation
   # source backend/venv/bin/activate

   # Install dependencies
   pip install -r backend/requirements.txt

   # Initialize database tables and seed synthetic demo records
   python backend/scripts/init_db.py
   python backend/scripts/seed_demo_data.py

   # Start FastAPI server (Port 8000)
   uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
   ```

4. **Frontend Setup:**
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
   *Open [http://localhost:5173](http://localhost:5173) in your browser.*

### Option B: Docker Compose (PostgreSQL)

If using Docker for PostgreSQL:
```bash
docker compose up -d
python backend/scripts/init_db.py
python backend/scripts/seed_demo_data.py
```

- `test_healthcheck`: Validates FastAPI and PostgreSQL connectivity.
- `test_login_invalid_credentials`: Rejects unauthorized logins with HTTP 401.
- `test_patient_login`, `test_clinician_login`, `test_admin_login`: Validates Argon2 verification and cookie session creation.
- `test_admin_forbidden_from_clinical_documents`: Proves administrators receive HTTP 403 when attempting to access medical records.
- `test_clinician_access_restricted_to_shared_docs_only`: Proves clinicians can only access documents explicitly included in active grants.
- `test_revoked_grant_denies_subsequent_access`: Proves that revoking consent immediately cuts off clinician access.

## 8. Security & Healthcare Compliance Design

- **Backend-Enforced Authorization:** Access control is strictly enforced on every FastAPI endpoint, not hidden in UI components.
- **Resource Ownership Verification:** Every request checks user role and consent relationships in PostgreSQL.
- **Argon2 Password Hashing:** Uses state-of-the-art Argon2id hashing algorithms.
- **Secure Server-Side Sessions:** Session cookies are HTTP-only, SameSite lax, with SHA-256 hashed session identifiers.
- **CSRF Token Protection:** State-changing API operations validate CSRF tokens.
- **Private Storage:** Medical documents are stored with random UUID filenames in a private backend folder outside the public web root.
- **Audit Logging:** Security and consent events are recorded without leaking clinical text into log files.
- **Synthetic Records Notice:** All medical records, names, and lab findings are synthetic demonstrations created for the hackathon.
